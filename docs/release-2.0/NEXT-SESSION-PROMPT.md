## Constraints discovered the hard way. Do not undo these.

- `react-native-google-mobile-ads` is pinned **`~16.3.4`**. Versions 16.4 and later pull play-services-ads 25.4.0, which carries Kotlin 2.3 metadata. RN 0.86 compiles with Kotlin 2.1.20, so the Android build fails in `:react-native-google-mobile-ads:compileReleaseKotlin`. Don't bump it without also raising the project's Kotlin version and running a full `assembleRelease`.
- In `app.json` plugins, `./plugins/withWidgetDeviceFamily` must stay listed **before** `@bacons/apple-targets`. apple-targets registers a provider mod, and Expo throws INVALID_MOD_ORDER for any mod added after a provider.
- In `locales/ios-hi.json`, every key must stay nested under `"ios"`. Top-level keys also become Android strings, and iOS-only `NSLocation*` keys then fail `lintVitalRelease` (ExtraTranslation).
- `modules/widget-data/package.json` must keep `"main": "index"` (no extension). With `index.ts`, Metro skips platform extensions and iOS silently gets the Android bridge.
- Fonts: Android embeds them through the `expo-font` plugin. iOS and web load them at runtime in `src/config/fontGate.runtime.ts`. Always `require` `@expo-google-fonts/*` by **subpath**, never from the package root.
- React Compiler is on, and eslint `react-hooks/*` errors mean the whole component bails out. **Lint is at 0 errors / 0 warnings, and the CI baseline in `.github/workflows/ci.yml` is 0/0. Keep it there.** Keep `??`, `?.` and ternaries out of `try` blocks inside components and hooks, because that is also a silent compiler bailout. You can check a file with `babel-plugin-react-compiler` (already installed).
- UI rules: English and Hindi only (Hindi in Devanagari). No IAST or Sanskrit chrome. No source attribution ("SOURCES.md", "Drik Panchang") in the UI. Route every user-facing string through `src/i18n/locales/en.ts` and `hi.ts` with key parity. Use `colors.accentText` for accent-coloured words and `colors.accent` only for fills.
- New SQLite migrations go on the ladder in `src/utils/database.ts` (the top is currently rung **12**). New persisted store fields bump `version` in `src/store/useStore.ts` (currently **17**) with a migration.
